# Batch A2b — The menu bar app

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this
> plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A menu bar agent that polls each sandbox on a timer, shows the link state as an icon,
and notifies on a transition or a critical event — calling the same `SandboxWatcher.poll` the CLI
calls, with its own cursor and its own liaison state.

**Architecture:** Every decision the app makes about *what to show* moves into `SandboxWatchKit`
with tests: which icon a `SandboxWatchReport` implies, and which report warrants a notification
with what title and body. The app target owns only what cannot be asserted — an `NSStatusItem`,
a `UNMutableNotificationContent`, a `Timer`, and the Keychain.

**Tech Stack:** xcodegen 2.46, AppKit + `NSStatusItem`, `UserNotifications`, `String Catalog`
(`Localizable.xcstrings`), Developer ID signing.

**Spec:** `docs/superpowers/specs/2026-09-17-supervision-dispositif-design.md`, §6.3 as amended
2026-09-18.

## Global Constraints

- `.macOS(.v13)` everywhere, matching `Package.swift`. Not the 14.0 of
  `Templates/AppKitTemplate/project.yml`.
- The Kit returns values; the surface decides policy (repo `CLAUDE.md`).
- Communication with Vincent in French; code identifiers, commits and doc files in English.
- No DMG and no notarization here — `Scripts/release.sh` belongs to batch 4.
- Never let the test suite reach the real Keychain or the network.

## What the spikes established (2026-09-18, run and removed)

These are measurements, not assumptions. Do not redesign around a guess where a number exists.

**1. xcodegen links a local package.** An app target built from this spec compiled against the
package and ran, printing the real contract (`X-Sandbox-Token 50 12`):

```yaml
packages:
  SandboxWatch:
    path: ..
targets:
  SandboxWatch:
    dependencies:
      - package: SandboxWatch
        product: SandboxWatchKit
```

An `info:` block is **mandatory**. Without one the build fails with
`Build input file cannot be found: .../Contents/Info.plist` — a build-system error that reads
like a missing source file and is not one.

**2. The Keychain ACL follows the signature and the bundle identifier, not the path.**
A Developer ID-signed `.app` reading the item `sbw` created:

| Run | Identity | Location | Time |
|---|---|---|---|
| first | `fr.lauriat.sandboxwatch.probe` | repo | **12.38 s** (one prompt, "Always Allow") |
| second | same | repo | **0.02 s** (silent) |
| third | same | `~/Applications` | **0.02 s** (silent — the move changed nothing) |
| fourth | `…probe2` | `~/Applications` | **5.24 s** (prompted again) |

This is the verified reason to sign with the stable Developer ID identity and to fix the bundle
identifier now: Vincent gets **one** prompt for the life of the app. An ad-hoc or unsigned binary
has a new identity every build, so it would prompt on every rebuild. Nothing here is a claim about
what signing does for notifications.

**3. Notifications could not be authorized from this session.** `requestAuthorization` returned
`granted=false` with `UNErrorDomain Code=1`, and `getNotificationSettings` reported
`authorizationStatus=denied` **before** asking — for a bundle identifier never seen on this Mac,
from `~/Applications`, Developer ID-signed with Hardened Runtime. So it is neither a cached user
denial nor a path problem. What it is — a machine-level setting, or this shell's session not being
able to grant it — was not established, and the plan does not pretend otherwise.

**Consequence for the design:** the app must treat authorization as a runtime condition it reports,
never one it assumes. An agent with no dock icon that silently fails to notify is indistinguishable
from a sandbox that is fine — the exact false negative this whole project exists to remove.

## Task 1: What a report means, in the Kit

**Files:**
- Create: `Sources/SandboxWatchKit/WatchPresentation.swift`
- Test: `Tests/SandboxWatchKitTests/WatchPresentationTests.swift`

**Interfaces:**
- Consumes: `SandboxWatchReport`, `Doctor.Finding.Kind`, `ChangeSeverity` (batch A2a).
- Produces: `StatusIcon` (`.healthy`, `.degraded`, `.unreachable`), `WatchPresentation.icon(for:)`,
  `Alert { title, body, severity }`, `WatchPresentation.alerts(for:sandbox:)`.

- [ ] **Step 1: Write the failing tests**

The cases that carry the design, each one a rule the app must not be free to reinvent:

```swift
func testAHealthyReportIsAHealthyIcon()
func testAnUnreachableFindingOutranksEveryOtherKind()
func testASilentReportProducesNoAlert()
func testATransitionAlwaysAlerts()
func testACriticalEventAlertsAndItsBodyCarriesTheServerMessage()
func testAnInformationalEventDoesNotAlert()   // it badges; it does not interrupt
func testOverflowAlertsBecauseSilentTruncationIsTheBugBeingAvoided()
```

`testACriticalEventAlertsAndItsBodyCarriesTheServerMessage` uses the real 2026-09-16 payload —
`collector_access_lost` / `governance` / the `AuthorizationFailed` message — because a notification
body naming only an identifier is what batch A1 deliberately left undone.

- [ ] **Step 2: Run them and watch them fail** — `swift test --filter WatchPresentationTests`.
- [ ] **Step 3: Implement `WatchPresentation`** — pure functions over the report, no AppKit import.
- [ ] **Step 4: Run the whole suite.**
- [ ] **Step 5: Prove the tests discriminate.** Two deliberate breakages, each expected to fail
      exactly one named test: make `alerts(for:)` fire on informational too, then make `icon(for:)`

## Task 2: The app target

**Files:**
- Create: `App/project.yml`, `App/SandboxWatch/AppDelegate.swift`,
  `App/SandboxWatch/NotificationPresenter.swift`, `App/SandboxWatch/Localizable.xcstrings`
- Modify: `.gitignore` (add `App/*.xcodeproj`, `App/.dd/`)

- [ ] **Step 1: Write `App/project.yml`** using the verified syntax above, with
      `LSUIElement: true`, `PRODUCT_BUNDLE_IDENTIFIER: fr.lauriat.sandboxwatch`,
      `MACOSX_DEPLOYMENT_TARGET: "13.0"`, and an explicit `schemes:` block — without one xcodegen
      generates no scheme and it is lost on every regeneration.
- [ ] **Step 2: `xcodegen generate` and build once** with a source file that only imports the Kit,
      to separate a spec error from a code error.
- [ ] **Step 3: Write `AppDelegate`** — one `NSStatusItem`, a 300 s timer, one menu item per
      sandbox read from `SandboxStore`, and per-surface state:
      `CursorStore(directory: "~/.config/sbw/cursors-app")` and
      `LiaisonStore(directory: "~/.config/sbw/liaison-app")`.
      **The liaison store matters as much as the cursor.** `poll` persists its decision
      unconditionally; sharing `liaison/` with `sbw watch` would let whichever polls first confirm
      the state, and the other would see `previous == observed`, decide no transition, and stay
      silent. A missed transition is the founding incident of this project.
- [ ] **Step 4: Write `NotificationPresenter`** — maps `Alert` to `UNMutableNotificationContent`,
      and exposes the authorization status so the menu can show
      "Notifications refusées — ouvrir Réglages" instead of failing silently (spike 3).
- [ ] **Step 5: FR + EN in `Localizable.xcstrings`.** Every user-facing string, including the
      refusal line above. Event types and Azure messages stay as the server sends them.
- [ ] **Step 6: Build, sign, run.**

```bash
cd App && xcodegen generate
xcodebuild -project SandboxWatch.xcodeproj -scheme SandboxWatch -configuration Release \
  -derivedDataPath .dd build CODE_SIGNING_ALLOWED=NO
ditto --norsrc --noextattr --noacl .dd/Build/Products/Release/SandboxWatch.app stage/SandboxWatch.app
codesign --force --options runtime --timestamp \
  --sign "Developer ID Application: Vincent LAURIAT (KFLACS69T9)" stage/SandboxWatch.app
codesign -dv --verbose=2 stage/SandboxWatch.app   # expect TeamIdentifier=KFLACS69T9, flags=0x10000(runtime)
```

- [ ] **Step 7: Commit** — `feat: a menu bar agent that polls with its own cursor and liaison`.
